# Source-bound automatic tagging queue

1. Target: MiniMax continuously produces semantic tags, psychology tags and keywords
   for a reviewed snapshot of readable Chinese sources, without new translations.
   User selected 標籤 on 2026-10-07; this authorizes the queue and its normal recovery.
2. Scope: tagging_queue helper, prepare command and durable manifest; auto-pipeline,
   supervisor, quota watcher, GUI launch/status, resume handoff and task installer.
   Corpus raw texts, translations, taxonomies and existing done tags are preserved.
   Local Windows desktop remains the execution host; the worker survives closing
   this session, resumes after quota reset, and the existing desktop watchdog restarts
   it after sleep/logon when running. No new Windows scheduled task is registered.
   Legacy callers passing 核心 route to the enabled job in the supervisor itself.
3. Execution: inventory source/tier/alias/completion; prepare disabled manifest with
   per-source SHA-256 and explicit deferrals; validate selection and runtime source;
   test worker and recovery paths; corpus verify; enable and launch hidden supervisor;
   observe real successful API replies and persisted tag output before completion.
4. Risks: wrong-language/partial/very short source; stale source after queue creation;
   restarting in the completed core queue; tag-only results inflating translation
   completion; concurrent workers; malformed queue paths; partial or content-rejected
   model output; committing unrelated work. These are observed existing boundaries,
   especially actual tier values 總集逐部 vs the unused literal 總集.
5. Responses: snapshot selected canonical sources and hashes, defer uncertain input,
   validate immediately before tagging, use existing checkpoint and generation locks,
   preserve independent metadata axes, force tag task for manifest worker, use shared
   persisted job at every recovery entrypoint. Source mismatch requires review;
   content rejection keeps its unresolved checkpoint. No shell string execution.
   Disable manifest and HALT at scripture boundary to roll back scheduling; retain
   generated tags and checkpoints. Default legacy behavior remains when no job exists.
6. Acceptance: malformed/duplicate/traversal entries rejected; empty/short/partial/
   changed source cases exercised; tag-only integration never calls translator or
   writes translation_status; rerun skips done and uses checkpoints; legacy supervisor
   argument and quota recovery target active tagging job; shared cross-process lock
   regression passes; full corpus verify before publication; live counts grow under
   one worker. A fixed snapshot with existing worker is simpler than a second runner
   or a general multi-stage scheduler. No website or annotation scope is added.
