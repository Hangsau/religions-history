# Implementation checklist — desktop status board correctness

> Confirmed by plan-check on 2026-07-20. This checklist covers the local
> `religions-history` Tkinter status board only.

## Target

The board shows one coherent live pipeline state, separates translation and
the two tag axes, exposes publication blockers, refreshes on exactly one timer,
and remains usable in a 560x700 window.

- [x] W2 `[manual]` Prefer valid, fresh `pipeline-runtime.json` values for the
  live slug/task/chunk; retain log-derived model, pace and recent activity.
- [x] W3 `[manual]` Handle absent, malformed, partial, old-schema and stale
  runtime state without crashing or falsely claiming live activity.
- [x] W4 `[manual]` Show separate translation, semantic-tag, psych-tag and

- [x] W5 `[manual]` Count incomplete `01-translation.md` files containing the

  `after` job.

- [x] W8 `[manual]` Add tests for conflicting state sources, malformed and

- [x] W9 `[manual]` Run unit tests, `git diff --check`, and

## Explicit exclusions

- Repairing failed translation chunks or changing their metadata.
- Clearing `pipeline-failed.json`.
- Changing MiniMax, checkpoint, quota watcher or supervisor behavior.
- Creating the missing project `MAP.md`.
- Committing or pushing the existing dirty worktree.

## Acceptance

- Runtime/log/Markdown disagreement displays the fresh runtime slug/task/chunk.
- Missing, malformed or stale runtime safely falls back to durable status/logs.
- Repeated manual refresh leaves one scheduled callback.
- All sections remain reachable at 560x700 through vertical scrolling.
- The board distinguishes four completion measures and reports failed-chunk
  publication blockers separately from the retry queue.
- Existing and new tests pass; `git diff --check` passes.
